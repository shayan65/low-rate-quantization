\caption{The recipe, and the two layouts it produces. \textbf{Offline}, each
covered matrix is rotated by a blockwise randomized Hadamard transform,
normalized in groups of 128, then quantized one column block at a time: within a
block the assignment is a nearest-neighbour search under the metric
$M = U_{JJ}^{-1}$, and the residual is propagated to the columns not yet
quantized. That is GPTQ generalized to a vector code, and it collapses to
textbook scalar GPTQ at dimension one, which we verify bit-exactly.
\textbf{Served}, the stored packing is not what runs. Five base-$K$ codes in a
\texttt{uint64} give an optimal $1.600$ bits of index but are inconvenient to
address, so a one-off unpack at load time yields one \texttt{int16} code per
group of weights, at $2.000$ bits. The rotation moves to the \emph{activation},
because the codes are stored in the rotated basis:
$y = \mathrm{rotate}(x)\,\widehat{W}^{\top}$. Quoting the storage rate as a
resident footprint, as earlier drafts of this work did implicitly, overstates
the served model by $25\%$ on the index.}
